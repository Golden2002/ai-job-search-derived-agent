## 补全项详细规格

### A1. 五维度职位匹配评分（新文件 job_evaluation.py）
基线：04-job-evaluation.md。实现：
- `EligibilityGate.evaluate(posting_text, profile) -> {verdict: PASS/FAIL/PROCEED_UNVERIFIED, quote, note}`——公民/PR/安全许可硬门（FAIL 硬停并引用原文；明确欢迎国际申请者 PASS；沉默 PROCEED_UNVERIFIED）
- `LanguageGate.evaluate(posting_text, languages) -> {verdict: PASS/FAIL/FLAG, note}`——要求语言不在语言表 FAIL；声明水平低于要求 FLAG；其余 PASS
- `evaluate_fit(posting, profile) -> {scores: {technical: 0-100, experience: 0-100, behavioral: 0-100, location: PASS/FAIL/FLAG+note, alignment: 0-100}, total: 加权分, verdict: Strong/Moderate/Weak/Poor, gaps: [缺失技能列表]}`
- 五维度：技术技能匹配（80-100 核心/60-79 大部分/40-59 部分/0-39 不匹配）、经验匹配（按职能而非职位头衔）、行为文化匹配、地点物流（通勤 PASS/远程 PASS/搬迁 FAIL/差旅 FLAG）、职业对齐动机

### A2. 相关性加权裁剪（新文件 cv_trim.py）
基线：05-cv-templates.md 裁剪规则。实现：
- `trim_experience(entries, target_role, max_items) -> (kept, removed)`——按三因子加权排序裁剪：职位相关性（0-1）、独特性（0-1）、依赖度（被其他条目引用的程度 0-1）
- 权重公式：score = 0.5*relevance + 0.3*uniqueness + 0.2*dependency
- 机械删除旧经历（纯时间排序）被禁止——必须按加权分数裁剪
- 返回裁剪建议报告（保留/移除理由）

### A3. 多职位批量评分排序（新文件 rank.py）
基线：.claude/commands/rank.md。实现：
- `rank_postings(postings: list, profile) -> list`——每个 posting 走 A1 五维评分，按 total 降序排序
- 输出含每个职位的评分明细 + verdict + gaps + 排名
- `--all` 等价语义：全部重评

### A4. 薪资基准对比（新文件 salary_benchmark.py）
基线：rank/评估相关。实现：
- `benchmark(role, region, years, sources: list) -> {percentile25/50/75, source_notes, verdict: 低于/符合/高于市场}`——输入职位/地区/年限，输出基准区间与对比结论；sources 留可扩展接口（用户可提供外部数据）

### B1. 面试准备（新文件 interview_prep.py）
基线：07-interview-prep.md。实现：
- `prepare(role, company, profile, jd_text) -> {star_stories: [...], tough_questions: [...], questions_to_ask: [...]}`——STAR 框架从 profile 经历生成故事（S/T/A/R 四要素）；高频难题映射；反问问题清单
- `simulate_interview(role, profile, rounds=1) -> Q&A 对话结构`（STAR 框架模拟面试）

### B2. 申请结果跟踪 + 跟进信（新文件 application_tracker.py）
基线：.claude/commands/apply.md + outcome.md。实现：
- `ApplicationTracker`——本地 JSON 存储（documents/applications/ 风格）：状态机 applied→interview→offer→rejected→withdrawn；记录日期/渠道/职位/联系人/备注
- `generate_followup(tracker_entry, days_since) -> 跟进信文本`——按时长分档（7 天/14 天/21 天）生成跟进信

### B3. 技能缺口分析 + 学习路径（新文件 skill_gap.py）
基线：upskill/SKILL.md。实现：
- `analyze_gaps(jobs: list, profile) -> {heatmap: {skill: {count, weight, provenance}}, plan: [{skill, priority, resources, order}]}`——技能频率图（记录缺口优先于推断）；权重 (100-fit)/100；学习计划按优先级排序
- 空白 fit_rating 不当 0 处理（跳过并计数）

### B4. profile 三维度（新文件 profile_3d.py）
基线：01-candidate-profile.md + 02-behavioral-profile.md + 03-writing-style.md。实现：
- `Profile3D` 数据结构：candidate（教育/经历/技能/发表/奖项）、behavioral（行为评估/优势/理想环境）、writing_style（语气/结构/禁忌清单——无 em-dashes 无陈词滥调等规则）
- JSON 序列化 + 校验

### C1. LaTeX 编译链 + 视觉校验（新文件 render/latex_compile.py）
基线：05-cv-templates.md（moderncv banking/blue、lualatex、2 页硬要求）+ cover_letters/cover.cls 资产。实现：
- `compile_tex(tex_path, workdir) -> {pdf_path, pages, warnings}`——调用 lualatex -interaction=nonstopmode（找不到则报清晰错误）
- `visual_check(pdf_text) -> {page_count_ok, orphan_heading_detected, font_consistent, issues}`——页数校验（!=2 报 FAIL）、孤儿标题检测（节标题后无内容）、字体一致性检查（文本层线索）
- 资产：复用仓库根 cover_letters/cover.cls + cv/main_example.tex 作为主模板源

### C2. 多模板注册/切换/导入（新文件 template_registry.py）
基线：05-cv-templates.md 多模板。实现：
- `TemplateRegistry`——注册模板（id/名称/描述/格式 tex|html|md/路径）、切换当前模板、导入自定义模板（校验文件存在+格式合法）、列出模板
- 内置至少：moderncv_banking（基线）、resume_html（现有 HTML）、generic_md

### D1. 事实校验（新文件 claim_gate.py）
基线：medical-resume-agent claim_gate/confirmation_gate。实现：
- `ClaimGate.review(claims: list, evidence: dict) -> {passed: [...], failed: [...], needs_confirmation: [...]}`——未确认信息不静默升级：无证据主张 FAIL/待确认；绝不编造
- `ConfirmationGate.ask(claims) -> 待确认问题清单`（用于 MCP 对话流）
- 语义：claim 分档 verified（有证据）/unverified（缺证据）/exaggerated（超出证据）

### D2. 多版本输出（core.py 扩展或新文件 multi_version.py）
基线：medical 多版本输出。实现：
- `generate_versions(content, target) -> {safe: 稳妥版, professional: 专业版, competitive: 高竞争力版}`——三版横向对比：稳妥版（保守陈述）、专业版（行业术语）、高竞争力版（量化成果+冲击力表达）

### D3. canonical-experience 六要素 schema（新文件 schemas/canonical_experience.py）
基线：schemas/canonical-experience-v2.schema.json（研究对象/方法/工具/角色/交付物 + 可迁移能力 + 目标方向表达）。实现：
- 六要素字段：research_subject（研究对象）、method、tools、role、deliverable、transferable_skill
- `decompose(raw_experience, target_direction) -> CanonicalExperience`——原始经历→六要素拆解→可迁移能力→目标方向表达重点（LLM 调用或规则+模板兜底）
- JSON Schema 校验函数

### D4. capability-taxonomy 对齐（新文件 capability_taxonomy.py 或 data 更新）
基线：medical capability-taxonomy.md。实现：
- 能力分类体系：结构化维度（研究/技术/协作/沟通/领导力等通用维度 + 领域维度）
- `tag_experience(experience, taxonomy) -> tags`——经历标签化
- data/capability_tags/general_v1.json 扩展对齐

### E1. 职位门户可扩展架构（新文件 job_portal.py）
基线：.agents/skills/ 6 门户 CLI 架构。实现：
- `JobPortalAdapter` 抽象基类：search(query) -> [posting]、detail(url) -> posting（posting 结构含 title/company/source/url/description/deadline）
- `PortalRegistry`——注册/列表/按名称获取
- 示例适配器：JSONFilePortal（本地 JSON 职位源，测试用）
- 说明文档注释：真实门户（LinkedIn/前程无忧/BOSS 等）按同接口扩展
