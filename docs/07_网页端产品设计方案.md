# 工具生态 · 网页端产品设计方案

> 波次 2 交付物（2026-08-23）· 覆盖：通用简历 / 外语词汇表 / 法律检索（语言规范校对网页端并入语言规范项目）
> 原则：完整用户闭环、体验流畅、前端可实现后端完整功能、与主项目 dock 集成（双模式：dock 调度 + 独立网页）

## 1. 通用简历网页端

### 用户流程（全链路闭环）

```
上传经历(PDF/TXT/MD) → 经历拆解与事实确认(内核层) → 输入目标JD
→ JD匹配评分(匹配/缺失标注) → 生成简历(STAR量化) → 三档横向对比(稳妥/专业/高竞争力)
→ 在线编辑(模板切换/手动微调) → ATS评分 → 导出(Word/PDF/HTML)
```

### 页面与交互

| 页面 | 核心交互 | 后端能力 |
|---|---|---|
| 1 经历摄入 | 文件上传 + 手动粘贴；拆解结果卡（方法/工具/角色/交付物）；未知项追问（≤3 问题） | `draft_experience` / `confirm_facts` |
| 2 JD 输入 | JD 粘贴/职业卡选择；匹配度仪表（评分 + 匹配项 ✅/缺失项 ❌） | `resume_match` |
| 3 生成预览 | 简历实时预览（3 风格模板切换）；每条 bullet 显示事实依据引用；三档 tab 切换对比 | `compose_bullets` / `rewrite_tier` |
| 4 在线编辑 | 富文本编辑（A4 实时预览）；修订后自动过 ClaimGate（未确认内容标黄） | `validate_claim` |
| 5 ATS 检查 | 通过率评分（关键词覆盖率/阅读顺序/联系方式完整性）+ 缺口建议 | `ats_check` |
| 6 导出 | Word/PDF/HTML 一键导出；打印样式 | `export_engine` |

### 设计要点
- 事实真实性可视：每条生成内容带"已确认事实"引用角标；未确认内容不可导出（ClaimGate 门）
- 三档对比视图：左右分栏或 tab 切换，高亮差异
- 响应式：桌面为主（简历编辑场景），移动端只读预览

## 2. 外语词汇表网页端

### 用户流程

```
上传PDF书籍 → 解析进度(OCR断裂修复状态) → 筛选设置(词频/词性/CEFR)
→ 词条浏览(全字段卡片) → 附件产物(词频榜/风格分析) → 渲染预览 → 导出(PDF/Word/MD)
```

### 页面与交互

| 页面 | 核心交互 | 后端能力 |
|---|---|---|
| 1 导入 | PDF 上传；解析进度条（提取/清洗/富化分阶段）；断裂修复报告 | `vocab_build` |
| 2 筛选 | 词频区间/词性/CEFR 等级/多语种 筛选器；实时统计（总词数/去重后/入选） | `vocab_entries` |
| 3 词条详情 | 全字段卡片：IPA 发音按钮/中英释义/词源树/原著例句（带页码）/搭配列表 | `vocab_lookup` |
| 4 附件产物 | 高频词榜（Top 100）/覆盖率/句式统计/风格分析/学习价值说明 | `vocab_artifacts` |
| 5 渲染导出 | 生命现象学 CSS 模板预览（A4 分页）；PDF/Word/MD 导出 | `vocab_render` |

### 设计要点
- 词条卡片信息密度：7 类字段分区展示，例句高亮目标词
- 筛选器即时反馈（防抖 300ms）
- 渲染模板锁定 Bell Jar 原版 CSS（禁止简化版）

## 3. 法律检索网页端

### 用户流程

```
输入问题 → 5要素校验(信息不全主动追问) → 用户分层识别 → 五阶工作流进度
→ 检索结果(法条+类案+推理) → 结构化报告(引用溯源/现行标注/存疑标注) → 导出
```

### 页面与交互

| 页面 | 核心交互 | 后端能力 |
|---|---|---|
| 1 提问 | 问题输入；分层自识别提示（普通人/法学生/律师/法官，可手改）；5 要素引导表单（争议类型/关键事实/管辖地域/时间节点/检索目标） | `legal_collect_facts` |
| 2 工作流进度 | 五阶进度条（问题解析→层级检索→冲突适用→时效梳理→报告）；每阶可展开查看 | `legal_research` |
| 3 结果视图 | 法条引用卡（效力层级/现行状态/优先级徽章）；类案列表（相关性排序/争点标签）；推理路径树（结论→法源连线） | `legal_search_cases` / `legal_reason` |
| 4 报告 | 结构化报告（章节/引用/存疑标注黄色警示/免责声明）；导出 md/html/docx | `legal_export` |

### 设计要点
- 存疑可视化：无法验证内容黄色警示角标 + 悬停说明，杜绝"看起来都确定"
- 引用溯源：每条法条点击展开（数据库/文号/效力状态/原文引用）
- 用户分层影响表述粒度（律师视角 vs 普通人视角切换）

## 4. 统一设计规范

| 项 | 规范 |
|---|---|
| 技术栈 | Flask API + 原生 HTML/CSS/JS（与主项目一致，无框架） |
| 视觉 | 与 PAEG 主项目 dock 风格一致；每工具独立品牌色 |
| 集成 | 主项目 dock 双模式：①外链独立网页（公网部署）②dock 内嵌对话调度（tool-resume/legal/vocab） |
| 可访问性 | 对比度 AA；键盘可操作 |
| 状态反馈 | SSE 进度流（长任务：构建/检索/生成）；错误 toast |

## 5. 验收标准（波次 4 网页端全量测试）

- [ ] 三工具全链路闭环可跑通（无阻塞 bug）
- [ ] 前端实现后端完整功能（无"按钮但后端没有"）
- [ ] 简历：事实门控（未确认不可导出）演示通过
- [ ] 词汇表：Bell Jar 模板渲染一致（禁简化）
- [ ] 法律：存疑标注 + 溯源演示通过
- [ ] 三工具响应式可用
